# JARVIS — Desktop AI Assistant

> Застосунок дозволяє користувачу взаємодіяти з локальною нейромережею (LLM) для ведення
> діалогу, виконання системних команд на Windows та **керування ПК з телефону через
> локальну Wi-Fi мережу** — без інтернету й хмарних сервісів.

---

## 1. Постановка задачі

**Контекст:** Сучасним power-users часто потрібен помічник не лише під час роботи за ПК,
але й коли вони знаходяться в іншій кімнаті — щоб вимкнути комп'ютер, перемкнути музику
або запустити фільм просто з телефону.

**Проблема:** Відсутність єдиного безпечного інструменту, який поєднує можливості ШІ,
керування операційною системою та віддалений доступ у межах домашньої мережі. Хмарні
рішення (ChatGPT, Claude) потребують інтернету й не мають доступу до локального ПК.

**Мета:** Створити десктопний застосунок на Qt/C++, який:
- запускає локальну LLM-модель (`.gguf` формат через `llama.cpp`);
- виконує системні команди через PowerShell/CMD на основі відповідей ШІ;
- піднімає вбудований HTTP/WebSocket-сервер у локальній мережі для прийому команд
  зі смартфона.

**Обмеження:**
- Платформа — Windows 10/11.
- Генерація тільки офлайн (локальна модель).
- Мережевий доступ — лише в межах домашньої Wi-Fi (без виходу в інтернет).
- Збереження даних — локально у JSON-файлах і QSettings.

## 3. Список екранів

### Головний екран (MainWindow)
- **Призначення:** Спілкування з ШІ, відображення поточного чату, введення команд.
- **Елементи UI:** QScrollArea з повідомленнями (MessageWidget), поле введення (QLineEdit),
  кнопка відправки/стоп, анімований фон (ParticleBackground), бічна панель зі статусом
  моделі та телеметрією.
- **Дані:** Повідомлення поточної сесії.
- **Дії:** Ввести запит, зупинити генерацію, перейти до налаштувань, відкрити історію,
  почати новий чат.

### Вікно налаштувань (SettingsDialog)
- **Призначення:** Вибір локальної моделі, зміна параметрів генерації та відображення.
- **Елементи UI:** QComboBox (вибір `.gguf` моделі), QSlider (температура, topK, topP,
  max tokens), QLineEdit (ім'я користувача, порт сервера), кнопки "Зберегти" / "Скасувати".
- **Дані:** Поточні значення GenParams, шлях до моделі, налаштування сервера.
- **Дії:** Змінити параметри, обрати іншу модель, налаштувати порт.

### Діалог історії чатів (ChatHistoryDialog)
- **Призначення:** Перегляд і завантаження попередніх сесій.
- **Елементи UI:** QListWidget (назва чату + дата), кнопки "Відкрити", "Видалити",
  "Новий чат".
- **Дані:** Список збережених JSON-файлів сесій.
- **Дії:** Відкрити сесію, видалити, розпочати нову.

## 4. Основні сценарії користувача

### Сценарій 1: Чат і генерація (основний)
1. Користувач відкриває застосунок.
2. Модель завантажується у фоні (`LlamaWorkerThread`).
3. Користувач вводить запит → натискає Enter або "▶".
4. ШІ стримить відповідь по токенах; [теги команд] приховані.
5. Відповідь збережено в JSON-файл поточної сесії.

### Сценарій 2: Виконання системної команди
1. Користувач пише: "Відкрий Discord".
2. ШІ генерує: "Запускаю Discord. `[CMD: open discord]`"
3. Тег перехоплюється, `tryLaunchKnownApp("discord")` знаходить exe.
4. `QProcess::startDetached` запускає Discord.exe.

### Сценарій 3: Робота з історією
1. Натиснути "Історія чатів".
2. Вибрати сесію зі списку.
3. Сесія завантажується — повідомлення відображаються у чаті.

### Сценарій 4: Керування з телефону (Local Network)
1. Застосунок піднімає HTTP/WebSocket-сервер на порту `8080`.
2. Користувач відкриває `http://<IP_ПК>:8080` у браузері телефону.
3. Вводить: "Вимкни комп'ютер через 10 хвилин".
4. Сервер передає запит у чергу `LlamaWorkerThread`.
5. ШІ генерує `[PS: shutdown -s -t 600]` → ПК виконує команду.
6. Відповідь ШІ повертається на телефон у JSON-форматі.

### Сценарій 5: Редагування та видалення сесії (після MVP)
1. Відкрити "Історія чатів".
2. Вибрати сесію → натиснути "Видалити".
3. JSON-файл видаляється з диску, сесія зникає зі списку.

## 6. MVP — Minimum Viable Product

### Ключовий end-to-end сценарій
> Запуск → завантаження моделі → піднятий локальний сервер → запит з телефону →
> обробка ШІ → виконання команди на ПК → відповідь повернена на телефон.

### Must-have функції (MVP)
1. ✅ Асинхронне завантаження `.gguf` моделі через `LlamaWorkerThread`.
2. ✅ UI чату зі стримінгом токенів (без блокування інтерфейсу).
3. ✅ Парсинг та виконання системних команд `[CMD:]` / `[PS:]`.
4. ✅ Збереження/завантаження сесій чату (JSON).
5. 🔲 **Локальний сервер на QHttpServer/QWebSocketServer (порт 8080).**
6. 🔲 **Простий HTTP API: `POST /query` → `{response: "..."}` для телефону.**

### Список функцій "після MVP" (backlog)
1. Гарний адаптивний веб-інтерфейс для телефону (PWA або SPA).
2. Авторизація/токен для підключення з телефону.
3. Захоплення stdout/stderr команд → показ результату в чаті.
4. Markdown-рендеринг у бульбашках повідомлень.
5. Багаторядкове введення (QTextEdit + Shift+Enter).
6. Автодетект формату промпту (ChatML vs Llama-3.1 vs Mistral).
7. GPU-офлоад (n_gpu_layers для NVIDIA/AMD).
8. Розпізнавання голосу (Whisper.cpp → voice-to-text).
9. Телеметрія ПК (CPU/RAM/GPU) у реальному часі на телефоні.
10. Системний трей (JARVIS у фоні).
