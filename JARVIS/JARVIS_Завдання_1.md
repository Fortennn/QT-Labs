# Завдання 1. Індивідуальний проєкт — JARVIS Desktop AI Assistant

---

## 1. Тема застосунку

Застосунок дозволяє користувачу вести діалог з локальною нейромережею на власному ПК,
отримувати відповіді без підключення до інтернету, виконувати системні команди Windows
голосом або текстом, а також керувати комп'ютером з мобільного телефону через локальну
Wi-Fi мережу.

---

## 2. Постановка задачі

**Контекст.** Цільовий користувач — технічно грамотна людина (програміст, ентузіаст,
geek), яка активно використовує комп'ютер і хоче автоматизувати рутинні дії: запуск
додатків, створення файлів, пошук інформації, керування медіа. Часто виникає потреба
виконати дію на ПК перебуваючи в іншій кімнаті — наприклад, вимкнути комп'ютер або
поставити на паузу музику, не встаючи з дивана.

**Проблема.** Хмарні AI-асистенти (ChatGPT, Copilot) потребують постійного з'єднання з
інтернетом, передають дані на зовнішні сервери й не мають прямого доступу до локальної
операційної системи. Жоден із них не може безпосередньо відкрити додаток, створити
папку або вимкнути ПК. Вбудований асистент Windows (Cortana) — обмежений і
прив'язаний до екосистеми Microsoft.

**Мета.** Розробити десктопний застосунок на C++/Qt, який запускає велику мовну модель
локально (файл `.gguf` через бібліотеку `llama.cpp`), надає користувачу зручний чат-
інтерфейс, виконує системні команди на основі відповідей ШІ та піднімає HTTP-сервер у
локальній мережі для керування з мобільного телефону.

**Обмеження:**
- Платформа — Windows 10 / 11 (x64).
- Генерація відповідей — виключно офлайн, через локальну модель.
- Керування з телефону — тільки в межах домашньої Wi-Fi мережі (без виходу в інтернет).
- Збереження даних — локально у JSON-файлах (історія чатів) і `QSettings` (налаштування).
- Збірка — CMake 3.20+, Qt 6.4+.

---

## 3. Сутності та дані

### ChatSession — Сесія чату
Ідентифікація: UUID (рядок без дефісів, генерується при створенні).

| Поле         | Тип              | Обов'язкове | Опис                                    |
|--------------|------------------|-------------|-----------------------------------------|
| id           | UUID (String)    | Так         | Унікальний ідентифікатор сесії          |
| title        | String           | Так         | Перше повідомлення користувача (≤60 символів) |
| updatedAt    | DateTime (ISO 8601) | Так      | Дата останнього повідомлення            |
| messages     | List\<Message\>  | Так         | Список усіх повідомлень сесії           |
| systemPrompt | String           | Ні          | Кастомний системний промпт для сесії    |

### Message — Повідомлення
Ідентифікація: порядковий індекс у масиві `messages` батьківської сесії.

| Поле  | Тип                    | Обов'язкове | Опис                          |
|-------|------------------------|-------------|-------------------------------|
| role  | Enum (user / assistant)| Так         | Хто написав повідомлення      |
| text  | String                 | Так         | Текст повідомлення            |
| time  | DateTime (ISO 8601)    | Так         | Час відправки                 |

### Settings — Налаштування застосунку
Ідентифікація: єдиний об'єкт, зберігається у `QSettings` (реєстр Windows).

| Поле          | Тип    | Обов'язкове | Значення за замовчуванням |
|---------------|--------|-------------|---------------------------|
| modelPath     | String | Так         | `models/model.gguf`       |
| temperature   | Float  | Так         | 0.80                      |
| contextSize   | Int    | Так         | 2048                      |
| maxTokens     | Int    | Так         | 1024                      |
| userName      | String | Ні          | (порожньо)                |
| serverPort    | Int    | Ні          | 8080                      |

### RemoteSession — З'єднання з телефону
Ідентифікація: IP-адреса клієнта + мітка часу підключення.

| Поле        | Тип      | Обов'язкове | Опис                              |
|-------------|----------|-------------|-----------------------------------|
| ipAddress   | String   | Так         | IPv4-адреса телефону              |
| connectedAt | DateTime | Так         | Час встановлення з'єднання        |
| deviceName  | String   | Ні          | Назва пристрою (з User-Agent)     |

## 4. Список екранів

### Екран 1 — Головне вікно (MainWindow)
**Призначення.** Основна робоча поверхня застосунку. Тут відбувається весь діалог з
нейромережею.

**Елементи UI:**
- Прокручуваний список повідомлень (`QScrollArea` з бульбашками).
- Однорядкове поле введення (`QLineEdit`) з кнопкою надсилання.
- Бічна панель: логотип, кнопки «Новий чат», «Історія», «Налаштування», індикатор
  статусу моделі, телеметрія (навантаження CPU/NPU).
- Анімований фон (частинки) для преміального вигляду.

**Дані:** Повідомлення поточної сесії (`ChatSession.messages`), ім'я користувача, назва
завантаженої моделі.

**Дії:** Ввести запит, зупинити генерацію, перейти до налаштувань, відкрити історію
чатів, почати нову сесію.

---

### Екран 2 — Налаштування (SettingsDialog)
**Призначення.** Дозволяє користувачу обрати локальну LLM-модель і тонко налаштувати
параметри генерації та вигляду застосунку.

**Елементи UI:**
- Поле вибору файлу `.gguf` (`QLineEdit` + кнопка «Огляд»).
- Повзунки (QSlider) для: температура, top-P, top-K, repeat penalty, max tokens.
- Поле для імені користувача та порту HTTP-сервера.
- Перемикач «Показувати час повідомлень».
- Кнопки «Зберегти» і «Скасувати».

**Дані:** Поточні значення з `QSettings` (Settings).

**Дії:** Змінити модель, відкоригувати параметри сэмплера, задати порт сервера,
зберегти або відхилити зміни.

---

### Екран 3 — Історія чатів (ChatHistoryDialog)
**Призначення.** Перегляд усіх збережених сесій та повернення до будь-якої з них.

**Елементи UI:**
- Список сесій (`QListWidget`): назва (перше повідомлення) + дата.
- Кнопки: «Відкрити», «Видалити», «Новий чат», «Закрити».

**Дані:** Метадані всіх JSON-файлів у директорії сесій (назва + `updatedAt`).

**Дії:** Відкрити вибрану сесію (завантажити всі повідомлення у головне вікно),
видалити сесію з диску, розпочати нову порожню сесію.

---

### Екран 4 — Онбординг (WelcomeDialog) *(показується лише при першому запуску)*
**Призначення.** Знайомство з застосунком та введення імені користувача.

**Елементи UI:**
- Привітальне повідомлення.
- Поле для імені (`QLineEdit`).
- Кнопка «Почати».

**Дані:** Ім'я зберігається у `QSettings`.

**Дії:** Ввести ім'я, підтвердити початок роботи.

---

## 5. Основні сценарії користувача

### Сценарій 1 (Стартовий): Запит до нейромережі
1. Користувач запускає застосунок.
2. Застосунок завантажує модель у фоновому потоці.
3. На бічній панелі з'являється статус «ONLINE».
4. Користувач вводить запит у поле та натискає Enter.
5. У чаті з'являється повідомлення користувача, а потім бульбашка ШІ, яка заповнюється
   токенами в реальному часі.
6. Після завершення генерації відповідь зберігається у JSON-файл поточної сесії.

### Сценарій 2 (Створення): Нова сесія чату
1. Користувач натискає «Новий чат» на бічній панелі.
2. Застосунок зберігає поточну сесію на диск (якщо є хоча б одне повідомлення).
3. Список повідомлень очищається, пам'ять моделі скидається.
4. Генерується новий UUID для нової сесії.
5. Користувач починає новий діалог.

### Сценарій 3 (Відкриття): Повернення до старої сесії
1. Користувач натискає «Історія чатів».
2. Відкривається діалог зі списком усіх збережених сесій (назва + дата).
3. Користувач обирає потрібну сесію та натискає «Відкрити».
4. Застосунок зберігає поточну сесію, завантажує обрану з JSON-файлу.
5. Всі повідомлення відображаються у головному вікні.

### Сценарій 4 (Видалення): Видалення сесії
1. Користувач відкриває «Історія чатів».
2. Вибирає сесію та натискає «Видалити».
3. Застосунок запитує підтвердження.
4. JSON-файл видаляється з диску, сесія зникає зі списку.

### Сценарій 5 (Виконання системної команди): Керування Windows
1. Користувач пише: «Відкрий Discord».
2. ШІ генерує відповідь: «Запускаю Discord.» і приховано вбудований тег `[CMD: open discord]`.
3. Застосунок перехоплює тег, знаходить шлях до `Discord.exe` через реєстр аліасів.
4. Додаток запускається через `QProcess`.
5. Тег не відображається користувачу — він бачить лише текст «Запускаю Discord.»

### Сценарій 6 (Опційний — після MVP): Керування з телефону
1. Застосунок піднімає HTTP-сервер на порту 8080.
2. Користувач відкриває `http://<IP_ПК>:8080` у браузері телефону.
3. Вводить запит у веб-форму та надсилає.
4. Сервер отримує запит, передає його у чергу нейромережі.
5. ШІ генерує відповідь і команду (наприклад, `[PS: shutdown -s -t 600]`).
6. ПК виконує команду; відповідь ШІ повертається на телефон у JSON-форматі.

## 7. Визначення MVP

### Ключовий end-to-end сценарій
> Користувач запустив застосунок → модель завантажилась → користувач ввів текстовий запит
> → ШІ згенерував відповідь у реальному часі → відповідь збережена і доступна після
> перезапуску.

### Must-have функції (MVP — 6 пунктів)
1. Завантаження локальної `.gguf` моделі через бібліотеку `llama.cpp` у фоновому потоці.
2. Текстовий чат-інтерфейс зі стримінгом токенів (без заморозки UI).
3. Перехоплення та виконання системних команд через теги `[CMD:]` і `[PS:]`.
4. Збереження поточної сесії у JSON-файл після кожного повідомлення.
5. Завантаження збереженої сесії після перезапуску застосунку.
6. Базові налаштування: вибір моделі, температура, розмір контексту.

### Функції «після MVP» (backlog — 10 пунктів)
1. Локальний HTTP/WebSocket-сервер для керування з телефону (порт 8080).
2. Веб-інтерфейс для мобільного пристрою (адаптивний HTML/JS).
3. Авторизація для HTTP-сервера (токен доступу).
4. Захоплення stdout/stderr команд і показ результату в чаті.
5. Markdown-рендеринг у бульбашках повідомлень (`**жирний**`, `` `код` ``, списки).
6. Автоматичне визначення формату промпту за назвою моделі (ChatML / Llama-3.1 / Mistral).
7. GPU-офлоад через параметр `n_gpu_layers` (NVIDIA / AMD).
8. Розпізнавання голосу (інтеграція `whisper.cpp` → voice-to-text).
9. Телеметрія ПК у реальному часі: CPU / RAM / GPU → відображення на телефоні.
10. Системний трей: JARVIS згорнутий у фоновий процес, реагує на хоткеї.

## 8. Критерії готовності MVP

### Обов'язкові екрани
- `MainWindow` з повністю робочим чат-інтерфейсом.
- `SettingsDialog` з вибором моделі та збереженням параметрів.
- `ChatHistoryDialog` зі списком збережених сесій та можливістю їх відкрити.
- `WelcomeDialog` при першому запуску.

### Сценарії, що мають проходити без помилок
- Запит → стримінг відповіді → збереження у JSON (без зависання UI).
- «Відкрий [додаток]» → процес запускається на ПК.
- «Закрий [додаток]» → процес завершується через `taskkill`.
- Перезапуск застосунку → останні сесії доступні в «Історії».
- Зміна моделі в налаштуваннях → нова модель завантажується і відповідає.

### Дані, що мають зберігатися після перезапуску
- Шлях до обраної моделі (`QSettings`).
- Параметри генерації: `temperature`, `topK`, `topP`, `maxTokens`, `contextSize` (`QSettings`).
- Ім'я користувача (`QSettings`).
- Всі сесії чату у вигляді JSON-файлів у директорії `AppData/JARVIS/sessions/`.
